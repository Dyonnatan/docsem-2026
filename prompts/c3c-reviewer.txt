Two worked examples, from generic wording patterns (no instance numbers in
them; do not copy their numbers into your answer):

(1) S-quant, generating the missing side -- and checking S-incl at the same
    time. Wording: "a base amount, plus a fraction of that base added on
    both day X and day Y", asked as "how much [does the added part] come to".
    Even though the query names only the added part, check whether the
    licensed answer is the added part alone or the base plus the added part
    (S-incl) crossed with how many times the fraction is added (S-quant):
      added_only,      once:    fraction*base
      added_only,      times_k: 2*fraction*base
      base_plus_added, once:    base + fraction*base
      base_plus_added, times_k: base + 2*fraction*base

    the two added_only rows), write one base_plus_added reading too, reusing
    the same observed numbers. This combination is missed often: a query
    that reads as "just the addition" can still license reading it against
    the base total, when the base is the same schedule the addition sits on
    top of.

(2) S-pct without the word "percent". A query about the difference between

    probability differences are conventionally reported as percentage
    points (side: points), i.e. the raw 0-to-1 difference times 100, not as
    a relative percentage change (side: relative). If only a raw

    schema yet), add the same difference multiplied by 100 as a `points`
    reading. Tag any reading that already multiplies a difference by 100 as
    `points`; tag any reading that divides a difference by a base value
    (a ratio, not a plain difference) as `relative`.
